# Простой файлообменник через VPS — подробная инструкция
 
Инструмент для передачи файлов между двумя компьютерами через промежуточный сервер (VPS). Состоит из трёх скриптов:
 
- **server.py** — работает на VPS, соединяет отправителя и получателя и пересылает данные между ними.
- **sender.py** — клиент-отправитель.
- **getter.py** — клиент-получатель.
## Как это работает
 
Скрипт `server.py` сам по себе умеет соединить только одну пару "отправитель + получатель" за раз. Чтобы оба компьютера могли одновременно и отправлять, и получать файлы друг от друга, на сервере запускаются **две отдельные копии server.py на разных портах** — по одному каналу на каждое направление:
 
- **Порт 10001** — канал: Компьютер A отправляет → Компьютер B получает
- **Порт 10002** — канал: Компьютер B отправляет → Компьютер A получает
На каждом компьютере лежат и запускаются оба клиентских скрипта — `sender.py` (для отправки) и `getter.py` (для приёма), настроенные на разные порты (см. таблицу в шаге 8).

## Что понадобится
 
- Банковская карта для оплаты VPS (обычно от ~100–300 руб/мес за минимальную конфигурацию).
- Компьютер с Windows, macOS или Linux.
- Установленный Python 3 на обоих клиентских компьютерах. Проверить, установлен ли он:
  - Windows: откройте **PowerShell** и введите `python --version`
  - macOS/Linux: откройте **Терминал** и введите `python3 --version`
  - Если команда не найдена — скачайте Python с [python.org/downloads](https://www.python.org/downloads/) и установите (на Windows при установке обязательно поставьте галочку **"Add Python to PATH"**).

## Шаг 1. Аренда VPS
 
Подойдёт практически любой провайдер VPS с поддержкой Ubuntu: Timeweb, Selectel, DigitalOcean, Hetzner, Vultr, REG.RU и т.д. Общий порядок действий одинаковый:
 
1. Зайдите на сайт провайдера и зарегистрируйте аккаунт (email + пароль, иногда нужно подтверждение по СМС).
2. Пополните баланс минимальной суммой или привяжите карту.
3. Найдите в панели управления кнопку **"Создать сервер"** / **"Заказать VPS"** / **"Create Droplet"** (формулировка отличается у разных провайдеров).
4. При создании сервера укажите:
   - **Операционная система**: Ubuntu 22.04 LTS (или любая свежая версия Ubuntu — 20.04, 24.04 тоже подойдут).
   - **Конфигурация**: минимальная — 1 CPU, 512 МБ–1 ГБ RAM, любой SSD от 10 ГБ. Этого более чем достаточно.
   - **Локация дата-центра**: любая, желательно географически ближе к вам для меньшей задержки.
   - **Способ аутентификации**: если предлагают выбор — выберите "Пароль" (проще для начала, SSH-ключ надёжнее, но сложнее в настройке новичку).
5. Подтвердите заказ и дождитесь создания сервера (обычно 1–5 минут).
6. После создания в панели управления сервером найдите и запишите:
   - **IP-адрес сервера** (например, `185.203.45.12`)
   - **Логин** (почти всегда `root`)
   - **Пароль** (если выбрали способ входа по паролю; часто присылается на email или показывается один раз в панели — сразу сохраните его в надёжном месте)

## Шаг 2. Подключение к серверу по SSH
 
SSH — это протокол для удалённого управления сервером через терминал.
 
### Windows
 
1. Нажмите **Пуск**, введите `PowerShell`, откройте приложение.
2. Введите команду, заменив IP на свой:
```
   ssh root@185.203.45.12
```
3. При первом подключении появится вопрос вида:
```
   Are you sure you want to continue connecting (yes/no/[fingerprint])?
```
   Введите `yes` и нажмите Enter — это нормально, так система запоминает сервер.
4. Появится запрос пароля: `root@185.203.45.12's password:`. Введите пароль от сервера. **Символы при вводе пароля не отображаются на экране вообще** (ни точками, ни звёздочками) — это нормальное поведение SSH, просто вводите вслепую и нажимайте Enter.
5. Если всё верно, вы увидите приветственное сообщение Ubuntu и приглашение вида:
```
   root@server-name:~#
```
   Это значит, что вы успешно подключились и все дальнейшие команды выполняются уже на сервере, а не на вашем компьютере.
 
Альтернатива для Windows, если стандартный `ssh` не работает: скачайте [PuTTY](https://www.putty.org/), укажите IP в поле "Host Name", порт 22, нажмите "Open", затем введите логин `root` и пароль.
 
### macOS / Linux
 
1. Откройте приложение **Терминал** (Launchpad → Терминал на Mac, или через меню приложений на Linux).
2. Введите ту же команду:
```
   ssh root@185.203.45.12
```
3. Далее все шаги идентичны варианту для Windows (подтверждение fingerprint, ввод пароля).

## Шаг 3. Обновление системы и установка зависимостей
 
Все команды в этом и следующих шагах выполняются **на сервере**, то есть в том же окне терминала, где вы уже подключены по SSH.
 
1. Обновите список пакетов:
```bash
   apt update
```
   Это обновляет список доступных программ, не сами программы. Займёт 10–30 секунд.
 
2. Установите Python и утилиту screen (о ней ниже, в шаге 6):
```bash
   apt install python3 screen -y
```
   Флаг `-y` автоматически подтверждает установку без дополнительных вопросов.
 
3. Проверьте, что всё установилось:
```bash
   python3 --version
   screen --version
```
   Должны вывестись номера версий (например, `Python 3.10.12`), без ошибок.

## Шаг 4. Создание серверных скриптов
 
Нужно создать на сервере два файла: `server1.py` (будет работать на порту 10001) и `server2.py` (порт 10002).
 
### Создание первого файла
 
1. Откройте текстовый редактор `nano` с новым файлом:
```bash
   nano server1.py
```
   Откроется пустой экран редактора прямо в терминале.
 
2. Скопируйте весь код из вашего файла `server.py` (Ctrl+C на вашем компьютере в редакторе, где он у вас открыт) и вставьте его в терминал (обычно правый клик мыши → "Вставить", либо Ctrl+Shift+V, либо просто Ctrl+V в зависимости от терминала).
3. Проверьте, что текст вставился полностью и без искажений.
4. Сохраните файл:
   - Нажмите `Ctrl+O` (буква O, не ноль) — это команда "Write Out" (сохранить).
   - Появится строка снизу с именем файла — просто нажмите `Enter`, чтобы подтвердить.
   - Нажмите `Ctrl+X`, чтобы выйти из редактора.
5. Проверьте, что файл создан и содержит код:
```bash
   cat server1.py
```
   Должен вывестись весь код скрипта.
 
### Создание второго файла (копия с другим портом)
 
Вместо повторного набора текста просто скопируйте первый файл и замените номер порта:
 
```bash
cp server1.py server2.py
sed -i 's/10001/10002/' server2.py
```
 
Разбор команд:
- `cp server1.py server2.py` — копирует файл под новым именем.
- `sed -i 's/10001/10002/' server2.py` — автоматически заменяет текст `10001` на `10002` внутри файла `server2.py` (флаг `-i` означает "изменить файл на месте").
Проверьте результат:
```bash
cat server2.py
```
Убедитесь, что в строке `server.bind(("0.0.0.0",10002))` теперь стоит `10002`, а не `10001`.

## Шаг 5. Настройка firewall и открытие портов
 
По умолчанию Ubuntu может блокировать входящие соединения на нестандартные порты. Нужно явно разрешить порты 10001 и 10002.
 
1. Проверьте текущий статус firewall:
```bash
   ufw status
```
   Если выведется `Status: inactive` — firewall выключен, можно переходить к шагу 5.2, но правила всё равно стоит добавить на будущее.
 
2. Разрешите нужные порты:
```bash
   ufw allow 22/tcp
   ufw allow 10001/tcp
   ufw allow 10002/tcp
```
   (Порт 22 — это сам SSH; его стоит явно разрешить, чтобы случайно не заблокировать себе доступ при включении firewall.)
 
3. Если firewall был неактивен и вы хотите его включить:
```bash
   ufw enable
```
   Подтвердите `y`, если спросит про возможное отключение SSH-соединений — так как порт 22 уже разрешён, это безопасно.
 
4. Проверьте итоговые правила:
```bash
   ufw status
```
   Должны отобразиться строки с портами 22, 10001, 10002 в статусе `ALLOW`.
 
**Важно:** у многих облачных провайдеров помимо firewall внутри Ubuntu есть ещё **отдельный firewall на уровне панели управления** (называется "Firewall", "Security Group" или "Сетевой экран" в веб-интерфейсе провайдера, вне SSH-сессии). Зайдите в панель управления вашим сервером в браузере и убедитесь, что порты 10001 и 10002 (TCP) разрешены для входящих соединений и там тоже — иначе подключение всё равно не пройдёт, даже если `ufw` настроен верно.

## Шаг 6. Запуск серверов через screen
 
`screen` — это утилита, которая позволяет запустить программу и оставить её работать даже после того, как вы закроете SSH-сессию или выключите свой компьютер.
 
### Запуск первого сервера
 
1. Создайте именованную сессию screen:
```bash
   screen -S server1
```
   Экран терминала очистится — вы внутри новой сессии.
 
2. Запустите сервер:
```bash
   python3 server1.py
```
   В консоли появится `new connection` — сервер запущен и ждёт подключений.
 
3. "Отсоедините" сессию, не останавливая сервер: нажмите `Ctrl+A`, отпустите обе клавиши, затем нажмите `D` (это два отдельных нажатия, не одновременно). Вы вернётесь в обычный терминал, а сервер продолжит работать в фоне.
### Запуск второго сервера
 
Повторите то же самое для второго порта:
 
```bash
screen -S server2
python3 server2.py
```
Затем снова `Ctrl+A`, потом `D`.
 
### Полезные команды screen
 
- Посмотреть список всех запущенных сессий:
```bash
  screen -ls
```
  Вы должны увидеть в списке `server1` и `server2`.
 
- Вернуться в сессию (например, чтобы посмотреть логи или перезапустить сервер):
```bash
  screen -r server1
```
 
- Находясь внутри сессии, снова отсоединиться: `Ctrl+A`, затем `D`.
- Полностью остановить сервер: зайдите в сессию (`screen -r server1`), нажмите `Ctrl+C`, чтобы прервать процесс, затем можно закрыть сессию командой `exit`.

## Шаг 7. Настройка клиентских скриптов
 
В файлах `sender.py` и `getter.py` есть строка с адресом подключения:
 
```python
socket.connect(("127.0.0.1",10001))
```
 
`127.0.0.1` — это "localhost", то есть "тот же компьютер". Его нужно заменить на настоящий IP вашего VPS, а номер порта — согласно таблице ниже, в зависимости от того, какой это компьютер и какой скрипт.
 
Откройте файл в любом текстовом редакторе (Блокнот на Windows, TextEdit на Mac, VS Code, Sublime Text — что удобно) и измените строку `socket.connect((...))` на нужные значения.
 
| Компьютер | Файл | IP для подстановки | Порт |
|---|---|---|---|
| A | `sender.py` | IP вашего VPS | 10001 |
| A | `getter.py` | IP вашего VPS | 10002 |
| B | `sender.py` | IP вашего VPS | 10002 |
| B | `getter.py` | IP вашего VPS | 10001 |
 
Пример итоговой строки для `sender.py` на компьютере A (при IP сервера `185.203.45.12`):
 
```python
socket.connect(("185.203.45.12",10001))
```
 
Сохраните файл после изменения. У каждого компьютера в итоге должны быть свои две версии `sender.py` и `getter.py` — с портами именно из своей строки таблицы.

## Шаг 8. Запуск клиентских скриптов
 
Скрипты запускаются локально, на компьютерах A и B, а не на сервере.
 
### Открытие терминала в папке со скриптами
 
- **Windows**: откройте папку со скриптами в Проводнике, зажмите `Shift` и нажмите правой кнопкой мыши на пустом месте внутри папки → **"Открыть окно PowerShell здесь"** (или наберите `cmd`/`powershell` в адресной строке проводника и нажмите Enter).
- **macOS**: откройте Терминал, введите `cd ` (с пробелом), затем перетащите папку со скриптами прямо в окно терминала мышкой — путь подставится автоматически — и нажмите Enter.
- **Linux**: аналогично macOS, через `cd /путь/до/папки`.
### Запуск получателя
 
На обоих компьютерах запустите (можно оставить работать постоянно, в фоне это не мешает):
 
```bash
python3 getter.py
```
(на Windows иногда команда называется `python getter.py`, без "3" — зависит от того, как был установлен Python).
 
В консоли должно появиться:
```
Ready for a transfer
```
Это значит, что скрипт подключился к серверу и ждёт входящие файлы.
 
### Отправка файла
 
Когда нужно отправить файл — на компьютере-отправителе запустите:
 
```bash
python3 sender.py
```
 
После сообщения `Ready for a transfer` скрипт выведет пустую строку и будет ждать ввода — введите **полный путь** к файлу и нажмите Enter.
 
Примеры полного пути:
- Windows: `C:\Users\ИмяПользователя\Desktop\document.pdf`
- macOS: `/Users/ИмяПользователя/Desktop/document.pdf`
- Linux: `/home/ИмяПользователя/document.pdf`
Подсказка, как быстро получить полный путь к файлу:
- Windows: зажмите `Shift`, кликните правой кнопкой по файлу → **"Копировать как путь"**.
- macOS: кликните правой кнопкой по файлу, зажмите `Option` → **"Копировать файл как путь"** (или перетащите файл прямо в окно терминала после ввода начала команды — путь подставится автоматически).
После нажатия Enter файл отправится, и скрипт снова будет ждать следующий путь — сессию можно не перезапускать, чтобы отправить несколько файлов подряд.
 
### Проверка результата
 
На компьютере-получателе в той же папке, откуда был запущен `getter.py`, должен появиться файл с тем же именем, что и на отправителе. Откройте его, чтобы убедиться, что содержимое передалось корректно.

## Часто задаваемые вопросы и устранение неполадок
 
| Проблема | Возможная причина и решение |
|---|---|
| `Connection refused` при запуске клиента | Сервер не запущен на этом порту — проверьте `screen -ls` и `ss -tulpn` на VPS (шаги 6–7) |
| `Connection timed out` | Порт закрыт firewall'ом — перепроверьте и `ufw`, и панель провайдера (шаг 5) |
| Клиент завис на "Ready for a transfer" не приходит | На этот порт подключён только один из двух скриптов — нужны оба (и sender, и getter) на одном и том же порту/канале |
| `Wrong adress` при вводе пути к файлу | Путь введён неверно или файл не существует по этому пути — проверьте точность пути, включая расширение файла |
| `python3: command not found` (Windows) | На Windows команда может называться `python` вместо `python3` — попробуйте `python getter.py` |
| `python3: command not found` (сервер) | Повторите `apt install python3 -y` (шаг 3) |
| Файл дошёл, но повреждён / не открывается | Убедитесь, что оба сервера (`server1.py` и `server2.py`) успели полностью получить и переслать данные — не закрывайте `sender.py` сразу после ввода пути, дождитесь возврата приглашения для следующего ввода |
| После перезагрузки VPS сервер перестал работать | `screen`-сессии не переживают перезагрузку сервера — после перезапуска VPS зайдите по SSH и снова выполните шаг 6 |
| SSH спрашивает пароль, но не принимает его | Проверьте раскладку клавиатуры (например, случайно включённая русская раскладка при вводе пароля из латинских символов) и Caps Lock |
